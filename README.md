# 🔥 MMR Oracle — анализ потенциального MMR в Dota 2

Premium-платформа аналитики Dota 2: вставьте ссылку на Steam / Dotabuff / OpenDota профиль
и текущий MMR — движок проанализирует **последние 200 рейтинговых матчей** и рассчитает:

- 🎯 **потенциальный MMR** (общий и по каждой из 5 позиций);
- 🏆 лучшие и худшие роли + рекомендацию, где апать быстрее всего;
- ⚔️ лучших героев, героев с **переоценённым винрейтом** и героев с высоким импактом;
- 📈 динамику формы, симуляцию подъёма MMR, серию побед/поражений;
- 🧠 текстовые инсайты модели и confidence-метрики;
- 🔗 shareable-страницу результата.

### Почему OpenDota

Источник выбирался из Steam API / OpenDota / Stratz / парсинга Dotabuff:

- **OpenDota** — открытый REST API поверх реплеев и Game Coordinator: отдаёт до 200 матчей
  одним запросом с GPM/XPM/уроном/лайнами, имеет публичные константы героев и щадящие
  лимиты (60 req/мин бесплатно, больше по ключу). Легален и стабилен. ✅
- Steam Web API отдаёт только «сырой» список матчей без статистики по игроку — пришлось бы
  делать 200 запросов деталей.
- Stratz (GraphQL) — хорош, но требует токен для любого запроса.
- Парсинг Dotabuff нарушает их ToS и ломается при каждом редизайне. ❌

## Быстрый старт (Docker)

```bash
cp .env.example .env        # при желании добавьте OPENDOTA_API_KEY / STEAM_API_KEY
```

### Переменные окружения

|---|---|---|

share-ссылок (результат живёт в sessionStorage клиента).

## Математическая модель

Полная реализация — `src/lib/engine/`.

### 1. Кривая winrate → MMR (diminishing returns)

```
Δ MMR = 930 · tanh((WR% − 50) / 15)
```

| WR | Δ MMR |
|---|---|
| 50% | 0 |
| 55% | +300 |
| 60% | +555 |
| 65% | +710 |
| 70% | +810 |
| 45% | −300 |

Каждый следующий процент винрейта даёт меньше рейтинга; кривая симметрична,
поэтому отрицательный винрейт опускает потенциал **ниже** текущего MMR.

### 2. Вес свежих игр

Экспоненциальное затухание с полураспадом 80 игр: `w(i) = 0.5^(i/80)`,
где `i = 0` — самый свежий матч. Последние ~80 игр определяют большую часть оценки.

### 3. Байесовское сжатие выборки

`WR* = (Σw·win + C·0.5) / (Σw + C)` — в выборку подмешиваются `C` псевдоигр
с винрейтом 50% (C = 12 общий, 10 на роль, 8 на героя). «3 игры, 100% WR»
больше не даёт +900 MMR.

### 4. Импакт, стабильность и роль

- **Импакт (0–100)**: KDA, GPM, XPM, урон по героям/строениям и саппорт-метрики
  (лечение + темп ассистов) нормируются на **бенчмарки конкретной роли** и
  взвешиваются весами роли; перебор смертей режет до 30% очков.
- **Стабильность (0–100)**: `100 − 2.4·σ(импакта)` — насколько ровно игрок перформит.
- **Модификатор сложности роли**: мид 1.05, керри 1.00, оффлейн 0.98, роумер 0.95, фулл-саппорт 0.92.

### 5. Итог

```
Потенциал = clamp( MMR + Δ(WR*)·roleMod + clamp((импакт−52)·6, ±180)
                        + clamp((стабильность−55)·1.5, ±90), 0…15000 )
```

- Роль с **< 20 матчами** → «Недостаточно данных», прогноз не строится.
- Герой: то же + фактор мастерства `min(1, games/15)`.
- **Confidence** растёт с числом игр и долей спарсенных реплеев.

### Определение позиции

OpenDota не отдаёт позицию напрямую — она восстанавливается из `lane_role`
(для спарсенных реплеев), `is_roaming`, приоритета фарма (GPM/ластхиты) и
архетипа героя: саппорт на сейф-лейне → pos 5, кор на оффлейне → pos 3 и т.д.

## API

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/analyze` | `{ profile, currentMmr }` → `{ shareId, result }` |
| `GET` | `/api/analysis/:shareId` | Сохранённый снапшот для share-ссылок |

Ошибки типизированы: `PRIVATE_PROFILE`, `ACCOUNT_NOT_FOUND`, `NO_RANKED_MATCHES`,
`RATE_LIMITED`, `UPSTREAM_RATE_LIMITED` и т.д. — фронтенд показывает каждую
своим состоянием. Rate limit: 6 анализов/мин с IP; повторный запрос того же
аккаунта в течение 30 минут отдаётся из кэша без похода в OpenDota.

## Архитектура

```
src/
├── app/                      # App Router: страницы, API-роуты, SEO (sitemap/robots)
│   ├── page.tsx              # лендинг: hero, форма, превью, формула
│   ├── analysis/[id]/        # shareable-страница результата
│   └── api/                  # POST /analyze · GET /analysis/[id]
├── components/
│   ├── ui/                   # shadcn-style примитивы (button, card, input…)
│   ├── home/                 # hero-секция, анимированный фон, форма
│   ├── analysis/             # дашборд: карточки, графики, медали, инсайты
│   └── layout/               # navbar, footer
└── lib/
    ├── engine/               # ⚙️ analytics engine: кривая MMR, роли, герои, инсайты
    ├── opendota/             # типизированный API-клиент + кэш констант
    ├── analysis-service.ts   # оркестрация: кэш → БД → движок → персист
    ├── steam.ts              # парсинг ссылок Steam/Dotabuff/OpenDota, vanity resolve
    ├── rate-limit.ts         # sliding-window limiter
    └── prisma.ts / cache.ts  # инфраструктура
```

Принципы: движок — чистые функции без I/O (легко тестировать), API-клиент
изолирован, UI получает готовый типизированный `AnalysisResult`. Для
горизонтального масштабирования in-memory кэш/limiter заменяются на Redis
за тем же интерфейсом.

## Диагностика (Troubleshooting)

**«Не удалось связаться с OpenDota» / «Источник данных недоступен»** — серверная
часть не смогла выполнить запрос к `api.opendota.com`. Откройте
**`http://localhost:3000/api/health`** — эндпоинт проверит доступ к OpenDota и
базе данных и покажет точную причину (таймаут, DNS, отказ соединения) с
подсказками. Типичные случаи:

- **Нет интернета у контейнера/сервера** — проверьте
  `docker exec <container> wget -qO- https://api.opendota.com/api/constants/patch`.
- **Сломанный IPv6 в Docker-сети** — хост резолвит AAAA-записи, но IPv6 не
  маршрутизируется, и fetch зависает. В Dockerfile уже включён
  `NODE_OPTIONS=--dns-result-order=ipv4first`; после обновления пересоберите
  образ: `docker compose up --build`. При запуске без Docker добавьте эту
  переменную окружения вручную.
- **Корпоративный прокси / файрвол** — Node fetch не читает системные
  настройки прокси; исходящий HTTPS к `api.opendota.com` должен быть разрешён
  напрямую.
- **OpenDota действительно лежит или отдаёт 5xx** — бывает редко; клиент сам
  делает 3 попытки с бэкоффом, дальше просто подождите. Статус:
  https://www.opendota.com.

Ошибки сети теперь логируются с первопричиной (`ENOTFOUND`, `ETIMEDOUT`,
`ECONNREFUSED`…) — смотрите вывод `docker compose logs web` или консоль
`npm run dev`.

## Ограничения

- Анализируются только ранкед-лобби; матчи короче 10 минут (ремейки) отбрасываются.
